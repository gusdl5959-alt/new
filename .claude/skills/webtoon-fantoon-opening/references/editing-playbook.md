# 편집 플레이북

오프닝을 실제로 완성하면서 효과가 있었던 것과 실패했던 것을 정리했다. 규칙이라기보다 판단 근거다. 곡과 소재가 다르면 숫자는 달라진다. 여기 나오는 모티프(인물 격자, 손글씨 구호 등)는 형식의 예시다. 새 작품에서는 그 작품의 원작에 근거가 있을 때만 쓰고, 내용은 그 작품에서 가져온다.

## 목차
1. 곡 구조별 처방
2. 박자에 맞춘다는 것
3. 트랜지션 고르기
4. 화면 글자
5. 반복 모티프
6. 장르별 조정
7. 소재가 모자랄 때
8. 자주 나는 실수

## 1. 곡 구조별 처방

| 구간 | 컷 길이 | 처리 |
|---|---|---|
| 인트로 | 2~3초 | 느린 푸시 인, 페이드 인. 작품의 상징물 한두 개만 보여 준다 |
| 내레이션·구호·독백 | 줄당 1컷 | 손글씨 타이포(`typo`)가 주인공. 그림은 한 톤 낮추고, 공포물이면 줄 끝에 2프레임 서브리미널 |
| 타이틀 | 2마디 | 곡의 첫 큰 타격에 제목을 꽂는다. 흰 플래시 + 색분리로 등장 |
| 인물 소개 | 박당 1명 | 2×2 보드(`quad`)에 박마다 한 명씩. 조·팀 단위로 묶으면 4박에 한 화면 |
| 스톱타임(뚝뚝 끊기는 타격) | 박당 1컷 | `hit`으로 적·라이벌·핵심 소품을 네거티브/흑백 번갈아. 본편에 나올 것의 예고 |
| 벌스 | 줄당 2~4컷 | 이야기 순서대로. 가사가 서술하는 것을 그대로 보여 준다 |
| 프리코러스 | 점점 짧게 | 마지막 1~2마디는 박당 1컷으로 가속하고, 코러스 직전 주인공 얼굴에서 2프레임 암전 |
| 코러스 | 1~4박 | 첫 박에 가장 센 액션 + 플래시·펀치·흔들림. 박자 펄스를 켠다 |
| 브레이크다운 | 2~3초 | 다시 느리게. 채도를 빼고 깜빡임(`flicker`). 앞의 챈트가 있으면 뒤틀어 재등장 |
| 파이널 코러스 | 1~2박 | 첫 코러스보다 흔들림·색분리·플래시를 1.5배. 서브리미널과 스트로브는 여기서만 |
| 아웃트로 | 길게 | 상징물로 줌 인하며 암전, 엔딩 타이틀. 마지막 타격이 있으면 글리치 한 번 |

코러스 평균 컷 길이는 1초 안팎이 기준이었다. 레퍼런스가 있으면 그쪽의 측정값을 따른다.

## 2. 박자에 맞춘다는 것

- 컷 시작 시각은 전부 `beats('A')(n)`으로 쓴다. 초 숫자를 직접 쓰는 것은 인트로처럼 박이 없는 곳과, `hits`로 확인한 특정 타격뿐이다.
- 4박 = 1마디. 가사 한 줄은 보통 2마디(8박)다. 줄 시작이 박 번호 몇인지 먼저 표로 만들어 두면 설계가 빨라진다.
- 가사는 박보다 살짝 늦게 들어오는 경우가 많다. 컷은 가사가 아니라 박에 맞춘다.
- 박자 펄스(`pulse`)는 박마다 화면이 1.5~5% 줌을 치는 효과다. 벌스 0.015, 코러스 0.03, 파이널 0.045~0.05. 박이 없는 구간에는 걸지 않는다.
- `stepz`는 한 컷 안에서 박마다 줌이 단계적으로 뛰는 스냅 줌이다. 정적인 컷(배경, 단체 샷)을 4박 이상 써야 할 때 리듬을 준다.
- 액션 클립은 `tin`(시작 지점)과 `speed`로 동작 정점을 컷 초반에 둔다. 5초짜리 클립의 동작이 2초에 터진다면 `tin=1.3, speed=1.3` 정도. `speed` 1.2~2.0은 속도감을 주고 30fps 소스의 미세한 끊김도 가려 준다.

## 3. 트랜지션 고르기

| `tr` 값 | 느낌 | 쓰는 곳 |
|---|---|---|
| (없음) + `punch` | 박에 꽂히는 하드 컷 | 기본. 줄 안의 모든 컷 |
| `whip_l/r/u/d` | 카메라가 휙 돌아감 | 가사 줄이 바뀔 때, 장소가 바뀔 때. 좌우를 번갈아 쓴다 |
| `zoom` | 화면 속으로 빨려 들어감 | 넓은 그림 → 가까운 그림, 추격·돌진 직전 |
| `glitch` | 화면이 찢어짐 | 일상 → 이상 현상으로 넘어갈 때 |
| `black` | 2프레임 암전 | 큰 타격 직전의 숨 고르기 |
| `flash=5` | 흰 섬광 | 코러스 첫 박, 타이틀 |
| `flash=5, redflash=1` | 흰색 뒤 강조색 | 파이널 코러스 첫 박 |

한 화면에 트랜지션 효과는 하나만. 휩과 플래시를 같은 컷에 겹치면 뭉개진다.

## 4. 화면 글자

- 손글씨 타이포는 가사 단어 타이밍에 맞춰 한 단어씩 써진다. 첫 줄(숫자·호칭)은 크게, 나머지는 2줄 이내.
- 글자는 왼쪽(`side='L'`) 또는 오른쪽에 붙는다. 인물이 가운데면 `c=(0.40, …)`이나 `c=(0.62, …)`로 반대쪽에 민다. 시트에서 겹치는지 꼭 본다.
- 타이틀은 한 줄. 강조할 부분만 강조색, 나머지는 종이색. 길면 엔진이 글자 크기를 줄인다.
- 부제·크레딧은 내가 지어 넣는 문구이므로 보고에 밝힌다.
- 가사는 메인 영상에 넣지 않고 SRT로 따로 준다. 가사를 얹은 참고본(`_가사자막`)과 후작업·업스케일용 글자 없는 버전(`_텍스트없음`)이 함께 나온다.

## 5. 반복 모티프

같은 클립을 두 번 쓰는 것은 결함이지만, 의도된 모티프의 변주는 구성이다. 효과가 좋았던 것:

- **인물 격자**: 코러스에서 인물 16칸이 박마다 채워진다(`grid_fill`). 가사에 "함께", "모두" 같은 말이 있을 때. 칸이 하나씩 꺼지는 변주(`grid_erase`)는 인물이 사라지는 것으로 읽히므로, 원작 전개와 스포일러 범위를 확인했을 때만 쓰고 꺼지는 순서가 임의라면 보고한다.
- **구호의 재등장**: 도입의 구호·대사가 브레이크다운에서 색과 글씨체를 바꿔 다른 의미로 돌아온다.
- **상징물 북엔드**: 첫 컷과 마지막 컷이 같은 상징물(문, 구멍, 탑).

`hit`, `sub`(서브리미널), `strobe`는 본편 클립의 한 프레임을 네거티브로 다시 쓰는 것이라 중복 검사에서 제외된다. 그래도 사용자가 중복으로 느낄 수 있으니 보고에 적는다.

## 6. 장르별 조정

`init(mood=…)`로 기본 색 보정을 고른다. 섬광·네거티브의 강조색은 `accent`, `flash_alt`로 바꾼다.

| 장르 | mood | 강조색 | 조정 |
|---|---|---|---|
| 공포·스릴러 | `horror` | 붉은색 | 서브리미널, 깜빡임, 네거티브 히트. 느린 구간을 확실히 느리게 |
| 액션·배틀·스포츠 | `action` | 작품 상징색 | 흔들림과 휩을 늘리고 서브리미널은 뺀다. `speed`를 높게 |
| 로맨스·드라마·일상 | `warm` | 따뜻한 색 | 흔들림·색분리·스트로브는 쓰지 않는다. 컷을 1.5~3초로 길게, 페이드와 느린 줌 위주. 펄스는 0.01~0.02 |
| 코미디 | `warm` 또는 `action` | 밝은 원색 | 박에 맞춘 스냅 줌(`stepz`)과 2×2 보드가 잘 맞는다 |

특정 컷만 다르게 하려면 `ok.GRADES['이름'] = (ok.make_lut(대비, 밝기, 감마, (R,G,B)), 채도)`로 추가한다.

## 7. 소재가 모자랄 때

- 정지 이미지도 컷이 된다. 느린 푸시(`z=(1.0, 1.1)`)나 빠른 가로 팬(`c`→`c1` + `hblur`)을 준다.
- 한 클립을 넓게 한 번, 박에서 스냅 줌(`stepz`)으로 당겨 한 번 더. 두 컷처럼 읽힌다.
- 인물 초상이 많으면 보드와 격자로 묶는다.
- 그래도 같은 장면을 다시 써야 하면 다른 구간(`tin`)과 반대 줌 방향으로 쓰고 `dup_ok=True`를 달고 보고한다.
- 꼭 필요한 장면이 없으면 억지로 메우지 말고, 어떤 컷이 필요한지 목록을 만들어 사용자에게 준다.

## 8. 자주 나는 실수

| 실수 | 증상 | 예방 |
|---|---|---|
| 전체 격자 하나로 박을 맞춤 | 후반 컷이 박에서 밀림 | 구간별 `grid` |
| 줌 트랜지션으로 격자·보드에 진입 | 빈 가운데를 확대해 검은 프레임 | 엔진이 막지만, 진입은 `flash`로 |
| 줌인 목표점 `c1`을 어림짐작 | 끝 프레임이 몸통·벽 | `frames`로 끝 프레임 확인 |
| 클립 길이보다 길게 사용 | 마지막 프레임에서 멈춤 | `edl`의 source range 경고 |
| 타이포가 얼굴 위 | 글자도 얼굴도 안 보임 | `side`와 `c` 조정 후 시트 확인 |
| 어두운 색 보정 + 비네팅 + 스트로브 | 화면이 거의 검정 | 스트로브 컷은 밝은 grade와 낮은 `vig` |
| 결함 테이크 사용 | 인물 복제, 화풍 변형이 그대로 나감 | inventory에 결함 시각 기록, `tin`으로 회피 |
| 미리보기만 보고 완료 선언 | 인코딩 결과의 문제를 놓침 | `qa` 시트를 완성 파일에서 확인 |
| 가사 전사 문구를 그대로 자막에 | 오탈자 자막 | 시각만 쓰고 문구는 원 가사 |
| 원작 조사 없이 가사·문구 작성 | 설정과 다른 내용 | 원작 기준표 먼저, 미확인은 넣지 않음 |
| 다른 작품의 모티프를 그대로 이식 | 원작에 없는 상징·규칙이 화면에 나옴 | 사례 파일은 문법만 참고 |
| 저해상도 소스를 키워 놓고 원본 해상도라고 보고 | 사용자가 화질 차이를 발견 | `qa`의 smaller-than-output 목록을 보고에 적음 |
