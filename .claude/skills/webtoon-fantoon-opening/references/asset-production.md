# 시작 이미지와 모션 생성

## 이미지 프롬프트

원작 참조 이미지를 실제 입력으로 넣고 유지할 부분을 명시한다. 참조 업로드를 프롬프트에 쓰는 것만으로 대신하지 않는다. 컷별로 다음을 한국어 문장으로 작성한다.

1. 컷 목적과 원작 상황.
2. 인물/괴물의 고정 외형과 소품.
3. 샷 크기, 시점, 카메라 위치, 배치.
4. 영상 시작 포즈와 행동 준비 상태.
5. 원작 그림체·선·색·조명. 승인된 조명이 있으면 그 버전 유지.
6. 16:9, 요청 해상도, 자막·워터마크를 추가하지 않는 출력 조건.
7. 그 컷에서 흔한 오류만 짧게 방지: 안경 추가, 인물 교체, 공 형태 변경, 팔다리 증식 등.

독립 후보 4장을 만드는 UI와 한 이미지 안에 4칸을 그리는 콜라주를 구분한다. 후보를 원하면 실제 배치 수를 사용하고 독립 파일로 받는다.

기존 이미지가 적절하면 다시 만들지 않는다. 잘못된 부분만 참조 편집으로 고친다. 같은 배경과 초상화의 명암만 바꿔 장면 수를 늘리지 않는다. 전신·어깨너머·낮은 시점·측면·넓은 공간·소품 근접·손과 눈의 디테일을 상황에 맞게 분배한다.

크로마키/투명 배경은 분리 합성이 실제 필요한 에셋에만 사용한다. 이미지 편집은 해당 생성/편집 도구의 지침을 따르며 얼굴이나 해부학적 형태를 임의의 후처리로 바꾸지 않는다.

## 모션 프롬프트

시작 이미지가 행동을 뒷받침해야 한다. 정면 초상화 한 장에 달리기·공격·컷 전환·여러 인물 교체를 동시에 요구하지 않는다. 한 클립에는 **한 번의 주요 행동**과 필요한 짧은 반응을 준다.

> 첨부 시작 이미지의 인물/괴물, 얼굴, 복장, 소품, 원작 선화와 조명을 유지한다. [준비된 포즈]에서 [한 번의 구체적 행동]을 한다. [팔다리·소품·방향·간격의 변화]. 카메라는 [고정/짧은 추적/낮은 시점 접근]. 끝부분은 [편집에 쓰기 좋은 마무리 포즈]. 새로운 인물, 물건, 능력, 얼굴 변형을 추가하지 않는다.

행동과 카메라를 구분한다. “강렬하게, 무섭게, 빠르게”만 쓰지 말고 움직이는 부위와 도착 위치를 적는다. 카메라 줌만 넣어 멈춰 있는 괴물의 액션을 대신하지 않는다.

공포 작품에서는 원작에 맞는 서로 다른 행동을 확보한다. 문틈으로 들어옴, 카메라 방향으로 한 걸음 접근, 고개와 시선이 먼저 돌아옴, 손이 내려옴, 원작 소품이 지나감, 인물이 책상 밑으로 피함, 문을 붙잡음 같은 샷을 실제 설정에 맞게 선택한다. 공·스피커·지점토 등 고유 대상을 일반 괴물로 바꾸지 않는다. 생성 전 원작에서 가능한 동작인지 확인한다.

빠른 편집은 생성 영상 하나에 수많은 트랜지션을 요구하기보다 안정적인 독립 샷을 확보하고 편집에서 만든다.

## 도구와 계정

현재 허용된 도구와 모델을 따른다. 이 사용자 기본 흐름은 컴퓨터 유즈로 지정 Chrome 프로필의 Flow 이미지 생성 → 지정 계정의 Magnific/클링 영상 생성이다. 실제 모델 옵션과 업로드 상태를 UI에서 확인한다. API나 숨겨진 네트워크 호출 권한으로 해석하지 않는다.

내장 이미지 생성이 허용되면 실제 참조 이미지 전달 방법으로 편집한다. 입력 파일이 없으면 확인하고 다른 원작 이미지를 사용했다고 가장하지 않는다.

영상 한 개만 허용되면 한 개씩 처리한다. 계정 교대가 허용되어도 같은 화면을 충돌하게 동시에 조작하지 않는다. x4도 실제 제공되는 경우에만 사용한다. 유료/크레딧 모드로 바뀌거나 요청한 무제한 모드가 없으면 자동 제출을 반복하지 않는다.

생성 기록에 컷/후보 ID, 모델, 실제 시작 이미지, 프롬프트, 제출·완료 상태, 다운로드 경로를 남긴다. 버튼을 누름, 생성 완료, 파일 다운로드를 구분한다. 같은 실패가 반복되면 계속 생성량만 쓰지 말고 입력·계정·큐를 확인하고 자료를 정리한다.

## 선별

다운로드 파일을 원작과 비교한다. 얼굴·머리·안경·복장·인물 수·괴물 구조·소품·공간을 먼저 확인한다. 높은 해상도와 멋진 조명은 닮지 않은 얼굴을 보상하지 않는다.

영상 처음·중간·끝과 행동 구간을 확인한다. 다른 인물이 등장하거나 공이 다른 형태로 변하거나 손·팔다리가 바뀌는 구간은 제외한다. 정상 구간의 부분 사용으로 충분하면 전체를 재생성할 필요는 없다. 행동이 없거나 시작 이미지부터 틀리면 고친 입력으로 다시 생성한다.

- planned: 계획/프롬프트만 있음.
- generated: 실제 파일 있음, 검수 전.
- approved: 확인한 사용 구간 기록.
- partial: 일부 정상 구간만 사용 가능.
- rejected: 이유와 수정안을 기록한 사용 불가 소스.

파일 존재만으로 approved를 부여하지 않는다. 자동 이미지 유사도는 찾는 보조 수단이며 정체성과 형태는 실제 화면으로 확인한다.
