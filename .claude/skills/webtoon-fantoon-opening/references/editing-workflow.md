# 편집 실행 순서

곡과 영상이 폴더에 있을 때 완성 MP4까지 가는 순서다. 원칙은 [editing-and-qa.md](editing-and-qa.md), 컷 처방은 [editing-playbook.md](editing-playbook.md), 파라미터는 [opkit-api.md](opkit-api.md)에 있다.

`<skill>`은 이 스킬 폴더, `<work>`는 프로젝트의 작업 폴더(`<프로젝트>/work`)다. 완성본은 work의 상위 폴더에 나온다. 원본 소재는 읽기만 한다. 각 단계 끝에 한두 문장으로 진행 상황을 알린다.

## 목차

## 1. 곡 분석

```bash
python3 <skill>/scripts/analyze_song.py scan "<곡>" --work "<work>"
```

초당 음량 막대, 템포 후보, 음량이 크게 변하는 초가 나온다. 이걸로 구간 표(도입, 절, 프리코러스, 후렴, 브레이크, 마지막 후렴, 아웃트로)의 시작·끝 초를 적는다. 그다음 구간마다 박자 격자를 따로 맞춘다.

```bash
python3 <skill>/scripts/analyze_song.py grid --work "<work>" --sections A:15.5-45.2 B:45.0-57.2 C:58.0-78.0 --bpm 180 200
```

구간별로 따로 맞추는 이유: 생성 음악은 템포가 미세하게 흐르고 구간 사이에 박이 밀리는 경우가 많다. 전체에 격자 하나를 쓰면 후반으로 갈수록 컷이 박에서 벗어난다. `--bpm` 범위는 scan의 템포 후보 근처로 좁혀야 배수 템포에 걸리지 않는다.

밴드가 터지는 순간, 음악이 뚝 끊기는 순간처럼 화면이 반드시 맞아야 하는 지점은 `hits`로 10ms 단위까지 확인한다.

```bash
python3 <skill>/scripts/analyze_song.py hits --work "<work>" 15.55 15.80
```

가사 타이밍은 `transcribe.py`로 얻는다. faster-whisper가 이 파이썬에 없으면 스크립트가 알려 준다. 그때는 기기에 이미 설치된 곳을 찾아 그 파이썬과 `--path`로 실행한다. 모델 다운로드나 패키지 설치가 필요하면 먼저 사용자에게 묻는다. 노래 전사는 단어가 틀리기 쉬우니 **시각만 믿고 문구는 실제 가사에서 가져온다.** 괄호 안 연출, 섹션 이름, 악기 지시는 자막에서 뺀다.

## 2. 소재 목록과 전수 검토

중복 파일부터 가린다. 파일명이 달라도 내용이 같은 파일이 흔하다.

```bash
python3 <skill>/scripts/media_inventory.py "<소재폴더>" --out "<work>/inventory.json"
```

그다음 눈으로 볼 시트를 만든다. 폴더마다 접두사를 다르게 준다.

```bash
python3 <skill>/scripts/contact_sheets.py clips  "<영상폴더>"  --work "<work>" --prefix C
python3 <skill>/scripts/contact_sheets.py clips  "<영상폴더2>" --work "<work>" --prefix N
python3 <skill>/scripts/contact_sheets.py images "<이미지폴더>" --work "<work>" --prefix I
python3 <skill>/scripts/contact_sheets.py refs   "<레퍼런스폴더>" --work "<work>"
python3 <skill>/scripts/fonts.py --work "<work>" --text "<작품 제목>"
```

클립은 `C00`, `N07` 같은 키로 불린다. 출력된 시트를 **한 장도 빠짐없이** 열어 보고 `work/inventory.md`에 클립별 메모를 남긴다.

- 무엇이 나오는가 (인물, 괴물·적, 장소, 동작)
- 동작의 정점이 몇 초인가 (애매하면 `contact_sheets.py dense --work <work> C06 C07`로 8프레임을 본다)
- 같은 장면의 다른 테이크인가 (테이크끼리는 한 번만 쓴다)
- 상태: approved(확인한 사용 구간 기록) / partial(일부 정상 구간만) / rejected(이유 기록). 파일이 있다는 것만으로 approved를 주지 않는다
- 결함: 인물이 둘로 복제됨, 얼굴·화풍이 실사로 변함, 원작에 없는 인물 등장, 소품 형태 변화, 손·팔다리 변형, 배경이 중간에 바뀜. 결함 구간은 피하고 멀쩡한 구간만 `tin`으로 잘라 쓴다

레퍼런스가 있으면 `refs` 출력의 평균·중앙 컷 길이와 10초당 컷 수를 본다. 이 숫자가 "얼마나 빠르게 자를지"의 기준이다. 몇 장만 보고 전체를 분석했다고 말하지 않는다.

이전 편집본을 통째로 붙이지 않는다. 원본 클립을 우선 쓰고, 필요하면 글자 없는 편집본의 좋은 구간만 가져온다.

## 3. 컷 설계

플레이북을 읽고 구간별로 설계한다. 핵심만 적는다.

- **모든 컷 시작은 박자 위에.** 시각을 초로 쓰지 말고 `A(8)`처럼 박 번호로 쓴다.
- **가사 한 줄에 2~4컷.** 빠른 구간은 한 박에 한 컷까지 간다. 컷 수만으로 빠르다고 주장하지 말고, 연타 뒤에는 시선과 공간을 읽을 시간을 준다.
- **가사와 그림을 맞춘다.** 맞는 컷이 없으면 분위기가 맞는 컷.
- **행동과 반응을 잇는다.** 위협의 준비/등장 → 접근/공격 → 인물의 회피·반응. 괴물 얼굴만 반복하거나 반응만 늘리지 않는다.
- **같은 클립은 전체 컷으로 한 번만.** 사용자가 가장 먼저 알아채는 결함이 장면 중복이다.
- **줄이 바뀌는 곳에 트랜지션, 줄 안에서는 하드 컷 + 펀치 줌.**
- **느린 구간을 남긴다.** 도입과 브레이크가 느려야 후렴이 빠르게 느껴진다.
- **뒤로 갈수록 세게.** 마지막 후렴은 첫 후렴보다 강하게. 단, 장르가 허용하는 범위에서. 음악이 커진다고 로맨스에 공포 연출을 넣지 않는다.
- **액션 클립은 정점을 박에 맞춘다.** `tin`과 `speed`로 정점이 컷 시작 0.3~0.6초 안에 오게 한다. 속도 변경은 행동이 실제 보이는 구간에만 쓴다.
- **스포일러를 만들지 않는다.** 얼굴 지우기, 빈자리, 인물 소멸 같은 연출은 원작의 운명과 요청된 스포일러 범위를 확인한 뒤에만 쓴다.

## 4. project.py 작성과 미리보기

`assets/project_template.py`를 `work/project.py`로 복사해 채운다. 완성된 사례는 `references/example/op44_project.py`에 있다. 사례는 문법과 값의 감각만 참고하고 내용은 가져오지 않는다.

```bash
python3 project.py edl      # 타임라인 + 검사(중복, 클립 길이 초과, 없는 소스)
python3 project.py sheet    # 컷마다 2프레임 → work/sheets/timeline_NN.jpg
python3 project.py seq tr1 18.08 8        # 18.08초부터 8프레임 연속: 트랜지션 확인용
python3 project.py frames chk 7.6 17.5    # 특정 시각의 프레임만
```

`edl`이 `CHECK OK`를 낼 때까지 고치고, `sheet`를 전부 본다. 시트에서 확인할 것:

- 글자가 인물 얼굴을 가리지 않는가 (가리면 `side`를 바꾸거나 `c`로 피사체를 반대쪽으로 민다)
- 줌인 끝 프레임이 엉뚱한 곳(몸통, 빈 벽)을 보고 있지 않은가
- 크롭이 얼굴·소품·중요 동작을 자르지 않는가. 단체샷은 모든 인물이 보이는가
- 너무 어두워 아무것도 안 보이는 컷이 없는가
- 트랜지션 직후 검은 프레임이 끼지 않았는가 (`seq`로 확인)
- 결함 구간이 들어오지 않았는가
- 타이틀의 한국어 철자가 맞는가

## 5. 렌더와 검수

```bash
python3 project.py all
```

검사 → 렌더(메인, 가사자막, 텍스트없음) → 음악 합치기 → SRT → 검수 → 컷리스트를 한 번에 한다. 길면 백그라운드로 돌린다. 끝나면 출력된 수치와 `work/sheets/qa_N.jpg`(완성 파일에서 1/3초마다 뽑은 프레임)를 전부 보고 확인한다.

| 출력 항목 | 볼 것 |
| --- | --- |
| 파일 규격 | 해상도·fps·길이가 의도와 같은가 |
| decode check | `clean`이어야 한다 |
| sources smaller than the output | 작은 소스를 키운 것이다. 보고에 "원본 720p"라고 쓰지 않는다 |
| frozen picture | 타이틀·의도한 정지 외에 긴 정지가 있으면 클립이 끝에서 멈춘 것일 수 있다 |
| black stretches | 각 항목이 의도한 것인가. 의도하지 않은 검은 구간은 버그다 |
| loudness | 원곡과 같은가, 피크가 0dB를 넘지 않는가 (엔진은 음량을 건드리지 않는다) |
| SRT 경고 | 시간 역전·겹침·곡 길이 초과가 없어야 한다 |
| qa 시트 | 설계와 다른 컷, 잘린 글자, 깨진 프레임, 메인에 가사가 들어가지 않았는지 |

문제를 고친 뒤에는 영향을 받은 실제 출력을 다시 확인한다. 파일명에 '최종'이 있다고 완료 처리하지 않는다.

## 6. 보고

1. 무엇을 만들었는지 한두 문장. 수행한 검수 수준(자동 디코딩, 대표 프레임, 연속 프레임)을 밝히고, 재생 확인은 못 했으니 싱크 체감 확인을 부탁한다.
2. 구성: 구간별로 무엇이 나오는지.
3. 검수 결과: 규격, 검은 구간, 음량.
4. 확인이 필요한 부분: 제외한 테이크와 이유, 확인 못 한 설정, 임의로 넣은 문구, 불가피하게 겹친 장면, 키워서 쓴 저해상도 소스.
5. 파일 목록: MP4, SRT, 컷리스트.

## 7. 수정 요청

"1분 10초에 사람 나오면 안 돼" 같은 요청은 컷리스트에서 그 시각의 컷을 찾아 해당 `S(...)` 줄만 고친다. 사용자가 "다른 영상이 있을 거야"라고 하면 inventory와 시트에서 같은 장면의 다른 테이크를 찾는다. 고친 뒤 그 구간을 `frames`로 확인하고 `all`로 다시 뽑아, 완성 파일에서 해당 구간 프레임을 한 번 더 본다. 큰 개편이면 `name`의 버전을 올린다(v1 → v2).

필요한 장면이 소재에 없으면 억지로 메우지 말고, 필요한 컷 목록과 이미지·모션 프롬프트를 [asset-production.md](asset-production.md) 형식으로 만들어 준다.
